# 03 – Build the Domain layer

## Goal

Create the `Book` entity and keep the basic book business rules inside the Domain project.

## 1. Create the folder

Inside `src/BookManagement.Domain`, create:

```text
Entities/
    Book.cs
```

## 2. Add the Book entity

```csharp
namespace BookManagement.Domain.Entities;

public class Book
{
    public int BookId { get; private set; }

    public string Name { get; private set; }

    public string Author { get; private set; }

    public int Quantity { get; private set; }

    public Book(string name, string author, int quantity)
    {
        if (string.IsNullOrWhiteSpace(name))
            throw new ArgumentException("Book name is required.");

        if (string.IsNullOrWhiteSpace(author))
            throw new ArgumentException("Author name is required.");

        if (quantity < 0)
            throw new ArgumentException("Quantity cannot be negative.");

        Name = name;
        Author = author;
        Quantity = quantity;
    }

    public void Update(string name, string author, int quantity)
    {
        if (string.IsNullOrWhiteSpace(name))
            throw new ArgumentException("Book name is required.");

        if (string.IsNullOrWhiteSpace(author))
            throw new ArgumentException("Author name is required.");

        if (quantity < 0)
            throw new ArgumentException("Quantity cannot be negative.");

        Name = name;
        Author = author;
        Quantity = quantity;
    }
}
```

## 3. Understand the entity

- `Book` represents a book in the business domain.
- `BookId` is the identifier. Its private setter prevents ordinary application code from assigning an ID directly.
- `Name`, `Author`, and `Quantity` also have private setters so changes go through the constructor or `Update` method.
- The constructor validates data before a new valid Book object can be created.
- `Update` applies the same rules when changing an existing book.

The `BookId` will be generated by the database through EF Core configuration.

## 4. Why validate in the Domain?

Request validation and domain validation serve related but different purposes.

- FluentValidation checks incoming API request data and can return user-friendly validation errors.
- Domain validation protects the entity's rules regardless of where the entity is created.

Do not rely only on API validation. Other code could use the Application layer without going through the HTTP controller.

## Checkpoint

Build the solution:

```powershell
dotnet build
```

The Domain project should compile without references to ASP.NET Core, EF Core, or Supabase.
